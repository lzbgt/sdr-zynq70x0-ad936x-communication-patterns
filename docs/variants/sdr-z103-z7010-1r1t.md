## Schematic Facts

The imported schematic text extraction supports these working facts:

- Zynq device: `XC7Z010-2CLG400I`.
- Debug path: FT2232HL, with JTAG nets `JTAG_TCK`, `JTAG_TDI`, `JTAG_TDO`, and
  `JTAG_TMS`.
- Serial path: FT2232HL UART nets `UART1_RX` and `UART1_TX`.
- Main USB path: USB3320 ULPI PHY with `USB_CLK`, `USB_D0..USB_D7`, `USB_STP`,
  `USB_NXT`, and `USB_DIR` into Zynq PS MIO.
- Boot-mode switch: extracted notes show `00 JTAG` and `10 QSPI` around
  `MIO[5:4]/DQ[3:2]`.
- GPS/control evidence includes `TIMEPULSE` and `AD9361_REF` nets.
- Targeted schematic text searches found no `RJ45`, `MDIO`, `MDC`, `RGMII`,
  `GMII`, `RMII`, common Ethernet PHY names, or physical Ethernet connector
  evidence. Treat network access as USB RNDIS only, not wired Ethernet.
- Targeted schematic text searches found no SD-card connector or SD
  command/clock/data nets. Treat Z103 as no-SD; use JTAG or another proven
  non-QSPI recovery path for pre-flash testing.

## Non-Destructive Next Workflow

1. Restore normal USB/RNDIS or another live read path, then capture a full Z103
   QSPI backup with `tools/backup_z103_qspi_live.sh` before any flash write.
2. Keep serial as the primary recovery/control path when JTAG reset experiments
   disturb USB gadget enumeration.
3. Extend the rebuilt Z103 path from U-Boot to Linux/rootfs from a clean
   USB/JTAG state, then verify USB RNDIS, IIO, and RF datapath.
4. Flash QSPI only after factory backup, JTAG recovery, rebuilt Linux runtime
   verification, and artifact correlation are proven.
